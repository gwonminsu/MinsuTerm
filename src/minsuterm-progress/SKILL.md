# 진행 보고 (minsuterm-progress)

프로젝트 폴더의 `progress/data.json`에 할 일과 끝낸 일을 적는다. 사용자는 MinsuTerm 사이드바에서 그 폴더의 **진행도 보기**를 눌러 터미널 영역에서 본다.
사용자가 페이지에서 남긴 요청과 확인은 `progress/inbox.jsonl`로 들어온다.

- 이 스킬은 `progress` 스킬과 같은 기록(`progress/data.json`)을 쓴다. 그러니 한 세션에서는 둘 중 하나만 쓴다.
  - MinsuTerm 안의 터미널에는 환경 변수 `MINSUTERM=1`이 있다. 두 스킬이 다 있으면 이 값이 있을 때 이 스킬을 쓴다.
- 기록은 MinsuTerm 화면에 그대로 보인다. 비밀번호, 토큰, 접속 문자열 같은 비밀정보는 항목·메모·공지에 적지 않는다.

## 부르는 법

모든 명령은 **프로젝트 폴더에서** 부른다. 사용자가 진행도 보기를 누를 폴더다.

- Git Bash:
  ```
  {{NODE}} "{{SKILL}}/scripts/cli.mjs" <명령> ...
  ```
- PowerShell: 맨 앞에 `&`를 붙인다. 명령 앞부분이 따옴표로 묶인 경로이면 `&` 없이는 PowerShell이 실행하지 않는다.
  ```
  & {{NODE_PS}} "{{SKILL}}/scripts/cli.mjs" <명령> ...
  ```
- 아래에서는 Git Bash 꼴로만 적는다. PowerShell에서는 늘 맨 앞에 `&`를 붙인다.

## 세션 시작

1. `show`로 지금 상태를 본다. 기록이 없으면 이때 빈 기록이 생긴다.
2. 사용자에게 **한 세션에 한 번만**, 한 줄로 알린다.
   - 예: "MinsuTerm 사이드바에서 이 폴더의 **진행도 보기**를 누르면 진행 상황을 볼 수 있어요."
   - 서버를 띄우거나 브라우저를 열지 않는다. 페이지는 MinsuTerm이 직접 띄운다.
3. Monitor로 `{{NODE}} "{{SKILL}}/scripts/watch-inbox.mjs"`를 지켜본다.
   - 새 줄 하나가 알림 하나가 된다.
   - Monitor는 최대 30분이라, 끝나면 다시 건다.

## 명령

칸 이름: `now`=지금 하는 것, `next`=다음에 할 것, `agent`=다른 에이전트가 하는 것, `hold`=보류

| 명령 | 하는 일 |
| --- | --- |
| `show` | 칸별 항목, 처리하지 않은 요청, 자러 가기 계획, 공지, 오늘 끝낸 일 개수를 본다. 기록이 없을 때 빈 기록을 만드는 것 말고는 파일을 고치지 않는다 |
| `batch "<이름>"` | 작업 묶음 이름을 바꾼다. 진행도는 이 묶음을 기준으로 센다 |
| `add <칸> "<제목>" ["<설명>"]` | 항목을 더하고 `#번호 제목`을 찍는다 |
| `move <번호> <칸>` | 항목을 다른 칸으로 옮긴다 |
| `wait <번호> [on\|off]` | '확인 필요' 표시를 켜고 끈다 |
| `detail <번호> "<설명>"` | 설명을 바꾼다 |
| `note <번호> "<내용>"` | 진행 메모를 시각과 함께 쌓는다 |
| `done <번호> [해시,해시] ["<설명>"]` | 칸에서 빼고 오늘 기록에 쌓는다. 설명이 없으면 항목의 설명을 쓴다 |
| `log "<제목>" [해시,해시] ["<설명>"]` | 칸에 없던 일을 오늘 기록에 바로 쌓는다 |
| `drop <번호>` | 항목을 지운다 |
| `req <요청번호> [added\|drop]` | 페이지 요청을 '할 일에 넣음'으로 표시하거나 지운다 |
| `notice add <id> "<내용>"` / `notice rm <id>` | 사용자가 해 줘야 할 일을 알리거나 지운다 |
| `sleep now` / `sleep done` | 잠든 시각 / 수면을 마친 시각을 적는다 |

- 커밋 해시는 소문자 16진수 6자 이상이다. 여러 개는 쉼표로 잇는다(`done 3 a1b2c3d,e4f5a6b "결과"`).
- 고치는 명령을 하나라도 부르면 Claude는 깬다(`asleepAt`이 지워진다).
- PowerShell 5.1에서 지킬 것:
  - 명령 맨 앞에 `&`를 붙인다(`& {{NODE_PS}} "..."`).
  - 빈 문자열 인자(`""`)는 사라진다.
  - 큰따옴표가 들어간 인자는 잘린다.
  - 그러니 제목과 설명 안에는 큰따옴표를 쓰지 않는다.

## 갱신 규칙

| 일어난 일 | 명령 |
| --- | --- |
| 새 요청을 받음 | `add next` |
| 항목을 시작함 | `move <번호> now` |
| 다른 에이전트에 맡김 | `move <번호> agent` |
| 사용자 확인이 남음 | `wait <번호>` |
| 진행함 | `note <번호> "…"` |
| 끝냄 | `done <번호> [해시] "결과"`. 커밋이 없으면 `done <번호> "결과"`로 쓴다. 해시 자리에 `""`를 주지 않는다 |
| 칸에 없던 일을 함 | `log "…"` |
| 하지 않기로 함 | `drop <번호>` |
| 사용자가 해 줘야 할 일이 생김 | `notice add <id> "…"`. 확인한 뒤 `notice rm <id>` |
| 새 작업 묶음을 시작함 | `batch "…"` |

- `data.json`은 직접 고치지 않는다. 항상 cli로 고친다.
- 항목을 시작하거나 끝낼 때마다 바로 갱신한다. 끝낸 뒤 몰아서 하지 않는다.
- 의미 있는 단계마다 note를 남긴다.
- 제목과 설명은 사용자가 알아듣는 말로 쓴다. 내부 함수 이름보다 "로그인 화면 검증 추가"처럼 쓴다.

## 페이지에서 오는 것 (watch-inbox 알림)

| 알림 | 할 일 |
| --- | --- |
| `요청 [번호] …` | 대화로 받은 요청과 똑같이 다룬다. 할 일에 넣었으면 `req <번호> added` |
| `요청 취소 [번호] …` | 사용자가 그 요청을 거뒀다. 하지 않는다. 이미 할 일에 넣었으면 시작 전이면 `drop`, 이미 하던 중이면 멈추고 어떻게 할지 묻는다 |
| `먼저 해 주세요 [번호] …` | 하던 일을 마치는 대로 그 항목부터 한다 |
| `자러 가기 [번호들] …` | 사용자의 직접 지시다. 아래 순서를 따른다 |
| `자러 가기 취소 …` | 하던 대로 계속한다 |
| `했어요 [id] …` | 실제로 됐는지 직접 확인한 뒤 `notice rm <id>`. 안 됐으면 `notice add <id> "…"`로 고쳐 다시 알린다 |
| `확인 답변 [번호] …` | 사용자가 '확인 필요' 항목에 남긴 답이다. 답은 그 항목의 메모에도 쌓인다. 답대로 처리하고, 더 기다릴 것이 없으면 `wait <번호> off`(끝났으면 `done`). 아직 물을 것이 있으면 `note`로 묻고 표시는 둔다 |

**자러 가기**를 받으면:

1. 고른 항목만 마저 끝낸다.
2. 다음 세션이 이어서 할 수 있게 남은 항목의 설명을 다듬는다(`detail`).
3. `sleep now`를 한다.
4. `minsuterm-dreaming` 스킬(없으면 `dreaming`)이 있으면 실행하고, 끝나면 `sleep done`을 한다. 둘 다 없으면 이 단계는 건너뛴다.
5. 고른 항목을 끝낼 수 없으면 `note`로 사정을 남긴다.

## 프로젝트 스코프

- 진행도 보기는 누른 폴더의 기록(`<그 폴더>/progress/data.json`)을 보여 준다. 페이지에서 다른 프로젝트로 바꾸지 않는다.
- 그러니 cli와 watch-inbox는 그 폴더에서 부른다.
  - 하위 폴더에서 부르면 기록이 하위 폴더에 따로 생겨서 진행도 보기에 보이지 않는다.
  - 하위 폴더에 있어야 하면 `PROGRESS_ROOT`로 프로젝트 폴더를 준다.
    - Bash: `PROGRESS_ROOT="<프로젝트 폴더>" {{NODE}} "{{SKILL}}/scripts/cli.mjs" ...`
    - PowerShell: `$env:PROGRESS_ROOT='<프로젝트 폴더>'; & {{NODE_PS}} "{{SKILL}}/scripts/cli.mjs" ...`
- cli를 한 번이라도 실행한 프로젝트는 `~/.claude/progress/projects.json` 목록에 들어간다. `progress` 스킬과 같은 목록이다.
- 페이지에서 누른 버튼(요청, 했어요, 먼저 해 주세요, 자러 가기)은 그 폴더의 `inbox.jsonl`로 간다. 처리는 그 폴더에서 watch-inbox를 지켜보는 세션이 한다.
- 진행도 보기의 **브라우저로 열기**로 연 페이지에서는 프로젝트 선택 화면에서 진행 기록의 이름을 바꾸거나 지울 수 있다.
  - 지우면 `progress/data.json`과 `inbox.jsonl`이 `~/.claude/progress/trash/<이름>-<시각>/`으로 옮겨지고 목록에서 빠진다. MinsuTerm 진행도 보기에는 "진행 기록이 지워졌어요"가 뜬다.
  - 휴지통에서 되살리거나 영구 삭제할 수 있다. 영구 삭제는 휴지통 안만 지운다.
  - 기억(메모리)·세션 기록·CLAUDE.md·프로젝트 파일은 어느 경우에도 건드리지 않는다.
- 지운 프로젝트에서 cli를 다시 부르면 빈 진행 기록이 새로 생기고 목록에 다시 들어간다. 사용자가 일부러 지운 기록이니, 사용자가 다시 시키기 전에는 그 프로젝트에서 진행 보고를 다시 시작하지 않는다.

## Claude의 방

페이지의 캐릭터는 데이터와 시각만 보고 상황에 맞게 움직인다. 그러니 기록이 실제와 맞아야 캐릭터도 맞게 움직인다.

- 메인 에이전트 캐릭터는 마지막으로 cli를 부른 에이전트를 따른다. Claude Code면 Claude(로고 빛살), Codex면 Codex(구름과 `>_`)다.
- 상황별 자리와 행동:

  | 상황 | 자리와 행동 |
  | --- | --- |
  | `now`에 진행 중인 항목이 있음 | 책상에서 타자 |
  | 안 누른 공지가 있거나 '확인 필요' 항목만 남음 | 앞으로 나와 손짓 |
  | 진행 중인 항목이 있는데 30분 넘게 변화가 없음 | 책상에서 꾸벅 |
  | `agent` 항목이나 안 끝난 서브 에이전트가 있음 | 탁자 옆에서 머그 들고 기다림 |
  | 대화 중이지만 할 일이 없음 | 안락의자에서 이야기 |
  | 그 밖 | 책, 커피, 물 주기, 기지개를 돌아가며 함. 오래 조용하면 졸고, 밤늦게는 하품 |

- 항목을 끝내면 축하하고, 페이지에서 누른 요청·'먼저 해 주세요'·'했어요'·자러 가기에는 말풍선으로 대답한다.
- 그러니 `now` 칸을 실제와 맞게 유지한다. 하는 일이 없는데 now에 남겨 두지 않고, 끝낸 일은 바로 done한다.
- 서브 에이전트를 맡길 때 description을 사용자가 알아듣는 말로 짧게 쓴다. 방의 이름표와 크루 목록에 그대로 보인다.
- 사용자는 방의 캐릭터를 우클릭해 세션 이름을 바꾸거나(`/rename`), 방에서 내쫓을 수 있다. 내쫓으면 MinsuTerm이 그 세션을 끝낸다(`/exit`). 메인 에이전트는 다음에 cli를 부르면 방으로 돌아온다.

## Codex에서 쓸 때

- 명령은 같다. 다만 cli를 부를 때 `PROGRESS_AGENT=codex`를 붙여야 Codex 캐릭터가 나온다.
  - Bash: `PROGRESS_AGENT=codex {{NODE}} "{{SKILL}}/scripts/cli.mjs" ...`
  - PowerShell: `$env:PROGRESS_AGENT='codex'; & {{NODE_PS}} "{{SKILL}}/scripts/cli.mjs" ...`
- 환경 변수 이름이 `CODEX_`로 시작하는 것이 있으면 붙이지 않아도 Codex로 본다.
- 세션 번호를 알면 `PROGRESS_SESSION_ID`로 넘긴다. 없어도 된다.

## 작업을 끝낼 때

- Monitor를 끈다.

## 주의

- 서버를 따로 띄우지 않는다. 페이지는 MinsuTerm이 127.0.0.1에서만 연다.
- `progress/`는 커밋하지 않는다. Git 저장소면 cli가 `.git/info/exclude`에 넣어 둔다.
